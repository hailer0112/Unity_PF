# 홍길동 플레이어블 캐릭터

## 디자인

동화 복구 요원인 젊은 검객. 참고한 전통 의상의 짙은 남색 도포, 아이보리 겹깃·바지,
붉은 허리띠와 금색 장식, 짚색 전통 모자와 흰 머리띠, 검은 머리, 발목 감개·신발,
허리의 검과 칼집을 결합했다. 탑다운 카메라에서 읽히는 굵은 의상 실루엣과
높은 명암 대비를 목표로 하는 스타일화된 3D 프로토타입이다.
기존 특정 만화·게임의 홍길동을 복제하지 않고, 옷의 겹침과 비대칭 장비로 앞뒤를 구별한다.
작은 책 모양의 가슴 장식은 동화 복구 요원이라는 설정을 표현한다.

직접 작성한 메시 생성기로 얼굴·의상·장비 메시와 URP Lit 머티리얼을 만든다.
기성 모델, 검색 이미지, 외부 텍스처를 게임 자산으로 가져오지 않는다.

## 구성

- `HongGildongVisual.prefab`: 모델과 관절, 동작 컴포넌트. 이동·입력을 소유하지 않는다.
- `Meshes/`: 지속 저장된 커스텀 메시 에셋.
- `Materials/`: 의상·피부·머리·금속용 URP 머티리얼.
- `HongGildongMotion`: 실제 속도로 대기와 걷기를 섞는 관절 기반 절차적 동작.
- `HongGildongBuilder`: 재현 가능한 제작 메뉴와 별도 프로젝트 검증 진입점.

관절 구조는 Hips/Chest/Head, 양쪽 허벅지/정강이, 상완/전완/손, 도포 자락,
머리카락과 머리띠 꼬리로 나눈다. 무기는 오른손 SwordSocket에 부착한다.
CharacterController와 PlayerMotor/PlayerAim/PlayerInputReader는 기존 것을 그대로 사용한다.
기존 Capsule Visual과 ForwardMarker는 비활성화하며 삭제하지 않는다.

## 동작과 조절

`HongGildongMotion`의 Stride Length는 한 걸음 주기의 이동 거리, Leg Swing은 다리 각도,
Blend Speed는 대기↔걷기 변화 속도다. 실제 수평 속도로 동작하므로 벽에 막혀 정지하면
걷기를 멈춘다. 조준 회전을 반영한 로컬 속도로 앞걸음·뒷걸음·옆걸음을 처리한다.
팔·상체·머리·옷자락·머리끈에도 보조 동작을 적용한다.

이 모델은 일러스트를 고품질 3D 캐릭터로 자동 변환한 결과가 아니다. Unity의 코드 생성 메시와 단색 재질을 이용한 스타일화된 시안이며, 새 모자와 장식은 Unity 에디터에서 직접 확인해야 한다.

이것은 스킨 메시, Humanoid Avatar, Animator Controller, 모션 캡처 결과물이 아니다.
관절에 부착된 메시를 코드로 움직이는 방식이며, 관절 연결·옷 관통·발 미끄러짐은
전문 스킨 리깅과 IK보다 한계가 있다. 공격·검 충돌·분신·구르기 판정은 구현하지 않는다.

## 확인 순서

1. Unity의 스크립트 가져오기가 끝났는지 확인한다.
2. 기존 MovementAimTest 씬에서 플레이어가 홍길동 외형인지 확인한다.
3. Tools > Fairy Tale Recovery > Apply Hong Gildong Redesign 메뉴를 Play 모드가 아닐 때 실행한다.
   기존 생성 모델을 새 프리팹으로 교체하고 Player.prefab과 열린 씬의 플레이어 외형을 반영한다.
   게임 루트/입력/이동/조준 컴포넌트는 변경하지 않지만, 기존 외형만의 수동 수정 사항은 초기화된다.
4. Console에 Hong Gildong redesign applied 메시지가 출력되면 열린 씬을 저장한다.
   GitHub에서 Pull만 하면 스크립트와 머티리얼은 받아지지만, 새 모자/메시는 메뉴 실행 전까지 생성되지 않는다.
5. Play 후 Game View를 클릭한다. WASD 이동과 마우스 조준이 유지돼야 한다.
6. 정지 상태의 호흡, 걷기, 반대 방향 이동, 옆걸음, 벽에 막힌 정지를 확인한다.
7. Player 아래 HongGildongVisual을 선택해 동작 변수를 조절한다.

## 학습 단원 연결

01: 클래스와 책임 분리. 02: 벡터·좌표 변환·삼각함수·쿼터니언.
03: Mesh·Material·Prefab·Hierarchy·컴포넌트·에디터 도구.
04: 기존 입력·이동·조준과 시각 반응 연결.
06: 외형·장비·행동의 기능 명세. 08: URP 재질과 조명에 따른 가독성.
이 목록만으로 최소 6개 단원 충족을 확정하지 않는다. 07 UI/UX 등 후속 게임 기능과
각 단원의 실제 플레이·테스트 증거를 별도로 확보한다. 절차적 동작을 Animator 활용으로
기록하지 않는다.
